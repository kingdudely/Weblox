# Wasmtime-ABI C++ imports for `out.full.o`

`tools/wasm2obj` compiles the patched WebClient module to a plain x86-64 ELF
object.  The 341 imported functions are **not** ELF undefined symbols: guest
code loads a function pointer out of the VMContext imported-function array and
calls it with the Wasmtime wasm-call convention.  This directory supplies those
341 pointers plus their metadata.

| File | Role |
| --- | --- |
| `gen_imports.py` | Regenerates `imports.h` and the generated part of `imports.cpp`. |
| `imports.h` | 341 `extern "C"` declarations, slot metadata, install/integration API. |
| `imports.cpp` | 267 stubs + 74 real implementations (hand-written region preserved on regeneration). |
| `IMPORTS.md` | This document. |

`host/vmctx.*`, `host/main.cpp` and the build files are owned by another worker;
they are referenced here but not modified by this change.

## 1. What was generated

* **341 function signatures**, in wasm import order (slot 1 … 341).
* Import index **0 is the shared memory** (`env.memory`, kind 2, min 4096
  pages / 256 MiB, max 65536 pages / 4 GiB, shared).  `docs/imports-wasm.json`
  labels it `"table"`; the binary says
  `memory`, and the generator accepts either spelling for that one entry.
* The first defined wasm function index is therefore **341**
  (`wb::kFirstDefinedFunction`); `_wasm_function_N` maps to wasm function index
  `N + 341` (e.g. `_wasm_function_0` is export `__wasm_call_ctors` at index 341).
* Signatures come from the **type section** of
  `/tmp/opencode/WebClient.raknet.wasm` (894 types), cross-checked against the
  type indices in `docs/imports-wasm.json` for all 342 imports.  Types present:
  `i32`, `i64`, `f32`, `f64`.  No multi-value imports exist (203 void results,
  127 i32, 8 f64, 3 i64), so no sret/indirect-result convention is needed.
* Names are stable: `wasm_import_<slot>_<name>`, e.g.
  `wasm_import_003_js_fetch_file`.  A slot's `ImportDesc` records module, name,
  signature string and wasm type index.

Regenerate with:

```sh
python3 host/gen_imports.py \
  --wasm /tmp/opencode/WebClient.raknet.wasm \
  --docs docs/imports-wasm.json \
  --out-dir host
```

The text between `BEGIN HANDWRITTEN IMPLEMENTATIONS` and
`END HANDWRITTEN IMPLEMENTATIONS` in `imports.cpp` is copied verbatim.  To
promote a stub, add its name to `REALIZED` in `gen_imports.py`, implement
`wasm_import_NNN_name` in that region, and regenerate.

## 2. Calling convention (x86-64 SysV, Wasmtime "wasm-call")

Generated wasm code calls the pointer stored in `VMFunctionImport.wasm_call`
directly.  There is no libffi/wasmtime trampoline in the object.

| Item | Location |
| --- | --- |
| Hidden callee `vmctx` | `rdi` (first argument) |
| Hidden caller `vmctx` | `rsi` (always passed; **not** a wasm arg) |
| Integer/pointer wasm args (`i32`, `i64`) | `rdx`, `rcx`, `r8`, `r9`, then stack |
| Float wasm args (`f32`, `f64`) | `xmm0` … `xmm7`, then stack |
| Stack args | callee-pops (`ret $N`), unlike SysV C |

Every generated import therefore declares **two** leading `void*` parameters
(`vmctx`, `caller_vmctx`).  Calling a wasm export with more than four GP
arguments from C directly corrupts `rsp`; use an asm shim that mirrors the
callee-pops convention (see `wb_call_thread_init` in `main.cpp`).
| Integer result | `eax` / `rax` |
| Float result | `xmm0` |
| Multiple results | not used by this module (would need sret) |

Each import is declared as:

```cpp
extern "C" int32_t wasm_import_003_js_fetch_file(
    void* vmctx, int32_t a0, int32_t a1, int32_t a2);
```

`void* vmctx` is deliberately untyped so this header does not depend on the
other worker's `vmctx.h`; it is the pointer the *calling wasm instance* passes,
and it is stored verbatim in every import slot's `vmctx` field.

### How import pointers are stored in VMContext

Source of truth: `wasmtime-environ-50.0.2/src/vmctxtypes.rs` and `vmtypes.rs`;
the concrete offsets for this module are generated by `host/gen_vmctx.rs` into
`host/vmctx_offsets.h`:

```
VMCTX_OFF_IMPORTED_FUNCTIONS = 72        (0x48)
VMCTX_NUM_IMPORTED_FUNCTIONS = 341
sizeof(VMFunctionImport)     = 32
```

`VMFunctionImport` (`repr(C)`) is:

```
+0  array_call     array-call ABI entry (needs a compiled array-to-wasm
+                  trampoline; none exists in out.full.o, left null)
+8  wasm_call      <- our wasm_import_NNN_* function pointer
+16 type_index     wasm type index of the import
+24 vmctx          hidden rdi argument for that call
```

A disassembly of `_wasm_function_0` shows the exact access pattern:

```asm
mov 0x28b0(%rcx), %rax     ; wasm_call of slot 324 (0x48 + 323*32 + 8)
mov 0x28c0(%rdi), %rdi     ; that slot's vmctx (0x48 + 323*32 + 24)
mov 0x68(%rsp), %rsi       ; caller's vmctx becomes first wasm arg
call *%rax
```

`wb::imports_install()` fills all 341 slots from the generated table:

```cpp
wb::imports_install(
    reinterpret_cast<wb::FunctionImportSlot*>(host::at(state.vmctx, VMCTX_OFF_IMPORTED_FUNCTIONS)),
    VMCTX_NUM_IMPORTED_FUNCTIONS, state.vmctx);
```

It also fills `type_index` from the type section.  `array_call` is left null on
purpose: putting a wasm-call function in that field would silently pass the
wrong arguments if a funcref to an import is ever called indirectly.  If the
host later compiles array-to-wasm trampolines, fill `array_call` from those and
keep `wasm_call` as-is.

## 3. Integration checklist (for the vmctx/main owner)

1. Add `imports.cpp` to the link line and add **`-lcurl`** (plus the existing
   `-lpthread -ldl -lm`).  Example: `$(CXX) ... main.cpp vmctx.cpp imports.cpp
   $(WASM_OBJ) -lcurl -lpthread -ldl -lm`.
2. In `host::setup`, after the shared memory is mapped, call
   `wb::imports_set_memory(state.memory_base, state.memory_def_storage.current_length)`.
   Without this, memory-reading imports log once and return safe values.
3. Replace the generic import-stub loop in `vmctx.cpp` with
   `wb::imports_install(...)` as shown above.  The generated pointers then
   replace `wasm_import_stub` for all 341 slots.
4. Wire the `memory.atomic.notify` builtin to
   `wb::imports_futex_notify(addr, count)` so the ported futex wait can be
   woken.  (The builtins array itself is owned by `vmctx.cpp`.)
5. Optional hooks for the re-entry points that need a guest call:
   `wb::imports_set_thread_entry()`, `wb::imports_set_wasm_callback()` and
   `wb::imports_store_headers()` (see §5).

No game/studio run is required to verify the table: `imports.cpp` compiles
standalone to an object with all 341 symbols defined.

## 5. Ports that need guest re-entry (documented, not faked)

These were ported from `v3-wasm2c/*.c` / `v2-wasmtime/src/imports/*.rs` only as
far as they do not need a wasm2c instance struct.  The remaining parts require
the table base or a per-worker VMContext, which `vmctx.cpp` owns:

* **embind invocation.**  Registration and the binding/type tables are real and
  queryable via `wb::embind_bindings()`, `wb::embind_find()` and
  `wb::embind_type()`.  Calling a binding needs the `__indirect_function_table`
  entry at `binding.invoker` and the guest `id` as its first argument (see
  `v3-wasm2c/embind.c:call_va`).  A native host must read the table base from
  `VMCTX_OFF_TABLES` and call the stored `wasm_call` pointer with
  `(table_vmctx, id, args...)`; no such call is invented here.
* **Async `emscripten_fetch` (slot #304).**  The libcurl download machinery is
  real and lives in `imports.cpp`; `emscripten_start_fetch` still needs the
  guest's `onsuccess`/`onerror` callbacks stored in the `emscripten_fetch_t`
  struct at offset 108.  Once the host can call those table indices, feed the
  response headers through `wb::imports_store_headers(fetch, text)` and the
  existing #305–#307 imports will serve them.
* **Worker entry points.**  `__pthread_create_js` really spawns a
  `std::thread` and manages a mailbox condvar, but entering the guest start
  routine needs a worker VMContext, per-worker TLS init and stack-limit setup.
  `wb::imports_set_thread_entry(start, arg, pthread_ptr)` is the explicit hook;
  without it `pthread_create` returns `EAGAIN` instead of pretending success.
  `_emscripten_init_main_thread_js` (#324) now re-enters the guest's
  `_emscripten_thread_init` / `_emscripten_tls_init` through
  `wb::imports_set_main_thread_init()` (wired in `main.cpp`), then arms the
  mailbox with the guest's own `pthread_self()` value.
* **Fibers / `Atomics.waitAsync` on the main thread.**  The futex wait is a
  real bounded host wait with a notify hook; a true JSPI-style parked fibre
  needs stack switching that `out.full.o` does not provide.  Unbounded waits
  are polled in 2 ms slices and capped at 30 s.
* **GL / WebGPU / WebSocket / OPFS / RNA.**  Left as stubs: implementing them
  would need either a browser-equivalent subsystem or guest callback dispatch
  through the wasm table.  A zero-returning stub is enough for boot, not for
  rendering or networking.

## 6. Verification performed

* Generator ran against the 102 MB patched wasm: 894 types, 342 imports,
  all type indices matched `docs/imports-wasm.json`; 341 signatures emitted
  (74 real / 267 stubs).

* `nm` on the object: all 341 `wasm_import_*` symbols defined, no missing
  import symbols (as expected, the object has zero undefined symbols).
* A bounded smoke test (`/tmp/opencode/imports_smoke.cpp`, no wasm execution)
  checked slot ordering, `imports_install`, canvas out-params, embind
  registration/lookup, futex not-equal, header bookkeeping, and log-once
  stubs.  It printed `[imports-smoke] OK`.
