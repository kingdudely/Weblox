# Wasmtime 50 `wasm_call` callee-pops ABI

## The bug

Every import in `g_calls[]` used to point directly at a C++ function that ends
with a plain System-V `ret`.  Cranelift's `Tail` calling convention (the
`wasm_call` ABI Wasmtime 50 uses for wasm→host calls) requires the callee to pop
the stack-passed arguments: `ret $imm16`.  Consequently the guest's `%rsp`
drifted by the pop amount at every import with stack args.  The first observed
victim was slot 21 (`emscripten_set_mousedown_callback_on_thread`, five
wasm args, 16 bytes of drift): the next import loaded a null `wasm_call` pointer
and jumped to `rip=0`.  Patching only slot 21's `ret` to `ret $0x10` moved the
fault to slot 23, proving the mismatch was systemic.  Evidence:
`host/MAIN_FAULT.md` on the `feat/cpp-main-fault` branch.

## Derivation of POP

Wasmtime 50.0.2 compiles wasm with `CallConv::Tail`
(`wasmtime-internal-cranelift-50.0.2/src/lib.rs:202`, `wasm_call_conv()`).
On x86-64, `cranelift-codegen-0.117.2/src/isa/x64/abi.rs` gives:

* `get_intreg_for_arg`: rdi, rsi, rdx, rcx, r8, r9 (six integer slots).  The
  wasm-to-array trampoline signature consumes rdi = callee vmctx and rsi =
  caller vmctx (`wasmtime-internal-cranelift-50.0.2/src/compiler.rs:236-244`),
  so **four** wasm integer args remain in registers (rdx, rcx, r8, r9).
* `get_fltreg_for_arg`: xmm0..xmm7, all eight available to wasm float args.
* `compute_arg_locs`: every stack arg occupies a slot of `max(size, 8)` bytes,
  slots follow wasm parameter order, and `next_stack` is rounded up to 16 at
  the end.
* `gen_return`: `CallConv::Tail` emits `ret frame_layout.tail_args_size`.

Therefore, for a wasm signature with `ni` integer (`i32`/`i64`) and `nf` float
(`f32`/`f64`) parameters:

```
stack_words = max(0, ni - 4) + max(0, nf - 8)
POP         = align_up(8 * stack_words, 16)
```

Generated from the actual type section by `host/gen_imports.py::abi_pop()`.
Distribution over the 341 imports:

| POP | slots |
|----:|------:|
|   0 | 282 |
|  16 |  44 (all of slots 21–35, slot 44/45, slot 58, …) |
|  32 |   6 (slot 40 `_embind_register_function`, slot 103/174/184/189/331) |
|  48 |   6 (GL tex/image calls) |
|  64 |   2 (slots 194/196) |
|  80 |   1 (slot 96 `rbx_wasm_rna_connect_js`, 14 integer args → 10 stack words) |

Incoming stack-arg placement was double-checked both ways: guest code at
`_wasm_function_147+0x69` (`0x95be59: mov %eax,(%rsp); 0x95be5c: call *%r10;
0x95be5f: sub $0x10,%rsp`) stores the fifth arg at the nominal SP before the
call; Cranelift's `SyntheticAmode::IncomingArg` resolves to
`[rbp + off + setup_area_size]` with `setup_area_size = 16`, i.e. `[entry_rsp +
8]`.  That is exactly where a System-V C function reads its first stack
argument, so the C++ bodies need no signature changes.

## What changed

`host/gen_imports.py` now also emits `host/abi_stubs.S` (build-time generated,
gitignored, regenerated by `make`).  For every slot it defines
`wasm_abi_NNN` and `g_calls[]` points there; the 341 C++ functions keep their
existing names and signatures.  Each thunk:

1. saves the guest return address in a per-thread stack
   (`wb_abi_ret_stack`, 256 entries, `wb_abi_ret_depth`),
2. overwrites the return address at `[rsp]` with a local `.Labi_ret_NNN` label,
3. `jmp`s to the C++ body (not `call`) so the body keeps the guest's `%rsp`,
   16-byte entry alignment and stack-argument layout,
4. at the label restores the guest return address and executes `ret $POP`.

Scratch registers are rax/r10/r11 only (Tail caller-saved, not argument
registers).  The epilogue deliberately does **not** touch rax or xmm0: they
carry the import's return value.  Depth overflow hits `ud2`, not random memory.

A naive `call body; ret $POP` thunk is *not* equivalent: the extra pushed
return address shifts the stack args by 8 bytes.  A controlled 5-argument test
(a guest-like caller + `call`/`ret $16` wrapper) read `0x4011…` instead of the
expected `42`; the TLS/`jmp` thunk reads `42` and leaves callee-saved registers
and depth balanced.  An earlier version of this patch used rax as epilogue
scratch and silently destroyed integer return values — ctors began trapping.
The final version avoids that; ctors are back to `returned normally`.

`--stubs-only` regenerates just the assembly file at build time without
rewriting `imports.h`/`imports.cpp`.  Regeneration is idempotent and preserves
both the hand-written region and the RNA forwarder block in `imports.cpp`.

## Verification (final build)

* `make` — success (only the pre-existing `.eh_frame_hdr` linker warning).
  `objdump -d demo` confirms `wasm_abi_021` ends in `ret $0x10` and
  `wasm_abi_096` in `ret $0x50`.
* `timeout 60s ./demo` — exit 0, `__wasm_call_ctors` returned normally,
  `RESULT=OK`.
* `timeout 90s ./demo --rna-probe` — exit 3 with
  `join attempt failed: empty .ROBLOSECURITY cookie` (expected when the cookie
  env is absent).
* One bounded join, `HOST_TRACE=1 WC_PLACE=189707
  WC_COOKIE_FILE=/home/john/mizg.txt WC_LOOP_MS=3000 timeout 90s ./demo`:
  - **Null-call fault gone.** Slots 21–35 all fire in order (previously the
    process died at slot 22 with `rip=0`); slots 44/45 (`ret $16`) and slot 40
    (`ret $32`) also fire during embind registration.
  - Guest reaches `initialize returned, code: 0`, `Setting up main loop`,
    slot 8 `schedule_main_loop` and slot 9
    `emscripten_exit_with_live_runtime`.
  - **No `main_loop_iteration` turns**: no `[rna-main] loop turns=` line.
  - **RNA imports did not fire**: `connects=0 connect_errors=0 callbacks=0/0`.
    Slot 96 (the 14-arg RNA connect, POP=80) was never reached, so its runtime
    behaviour is not validated by this run.
  - Remaining failure: after slot 9, a worker thread reports
    `throw_ref: no guest handler found` → `raise builtin -> ud2` → SIGILL,
    reported on the main export as `trapped via signal 4`; the other worker
    threads then re-raise unguarded signals and the process ends with SIGSEGV.

## Remaining blockers / scope notes

1. `emscripten_exit_with_live_runtime` (slot 9) is a stub that returns 0 rather
   than suspending/keeping the runtime alive.  Bootstrap reaches "Setting up
   main loop" but the export then takes a trap path; this is a semantics gap,
   not an ABI one.
2. The worker-thread exception has no guest handler and the SIGILL/SIGSEGV is
   re-raised on threads without an export trap guard (`unwind.cpp`, `main.cpp`
   — read-only for this task).
3. With the thunks, `HOST_TRACE`'s `ret=` field shows the thunk epilogue
   address instead of the guest return address (the real one is in TLS).
   Diagnostics only; argument logging is unchanged and now shows correct
   stack-passed values.
4. No import signature has more than eight float args, so there are no
   float-on-stack cases in this module.  Slot 58 mixes five ints and one float
   (POP=16) and is handled correctly by the generic rule.
5. RNA forwarders (slots 86–97) need no special ABI handling: they are normal
   C++ bodies behind the same generated thunks (slot 94 POP=16, slot 96 POP=80).
