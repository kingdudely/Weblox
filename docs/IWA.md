# IWA — the browserless path

The app now runs as a Chrome **Isolated Web App**. No Tauri, no Rust UDP
helper, no WebSocket bridge, no COEP juggling, no pointer-lock shim, no audio
clamp. Everything is JS + the patched wasm.

```
isolated-app://<bundle>
  index.html
  boot.js        loader globals, Trusted Types policy, Worker patch
  abi.js         ring layout, generated by tools/patch.py
  rbx-net.js     roblox.com -> controlled frame (fetch + XHR)
  rupp.js        TLV1/TLV2 rewriting, port of app/rkhost/src/rupp.rs
  ring.js        tx/rx rings <-> one UDPSocket
  auth.js        <controlledframe> login, gamejoin, join script
  app.js         boot order
  engine/*       patched wasm + glue, proxied from rbxcdn by rkhost
```

Measured live against place `13569002876` on Chrome 156 / Linux:

```
tx 1856 datagrams   rx 2220 datagrams   850 KB replicated in 55 s
canvas 1366x593, place rendering, no helper process on the machine
```

## Why this shape

Three browser rules made the old design need a helper:

| Rule | How the IWA answers it |
| --- | --- |
| `SharedArrayBuffer` needs cross-origin isolation | IWAs are cross-origin isolated by default |
| A page cannot open a UDP socket | `UDPSocket` (Direct Sockets), IWA-only |
| `gamejoin.roblox.com` is origin-locked and the cookie is `HttpOnly` | `<controlledframe>` is a real roblox.com context: same-site fetch, cookie attached by the browser |

The fourth problem — the session the server hands back depends on the client
identity that asked — is solved with the frame's `WebRequest` interceptor, which
rewrites `User-Agent` to `Roblox/WinInet` on `gamejoin` only.

## The join, exactly

1. Frame loads `https://www.roblox.com/home` with `partition="persist:roblox"`.
2. `whoami()` → `GET https://users.roblox.com/v1/users/authenticated` from
   inside the frame. 200 means logged in.
3. Not logged in: the frame is shown and the user logs in once. The partition
   keeps it. (Alternatively `injectCookie()` writes `.ROBLOSECURITY` into the
   frame's jar from inside its own origin — Chrome allows overwriting an
   HttpOnly cookie from script; only reading it is blocked.)
4. `join(placeId)` → `POST /v1/join-game` with the native client's body.
5. **`status: 0` is not an error.** A fresh attempt answers `0` with a
   `"JoinPlace=<id>;"` placeholder and `2` once the job exists. Retry while 0.
6. **Do not use `joinScriptUrl`.** `assetgame.roblox.com/Game/Join.ashx` now
   answers `301 -> /request-error?code=404`, in curl and in the browser alike.
   Post the join again **with the returned `jobId`** and the join script comes
   back inline as an object (`joinScript`), 70 fields.
7. `UDPSocket({remoteAddress: UdmuxEndpoints[0].Address, remotePort: port})`,
   `const { readable, writable } = await socket.opened`.
8. `ring.start()` points the seam at that socket; `/engine/WasmPlayer.js` loads
   after, so RakNet never wakes up without a destination.

## What Direct Sockets actually look like (Chrome 156)

The streams come from the **resolved `opened` promise**, not from the socket:

```js
const s = new UDPSocket({ remoteAddress, remotePort });
const { readable, writable, localPort } = await s.opened;   // not s.writable
await writable.getWriter().write({ data: bytes });          // not bytes
```

`socket.writable` is `undefined`; the instance only has `opened`, `closed`,
`close`. `write()` takes a `UDPMessage` (`{data}`), and `read()` yields one.

## RUPP, in JS now

Same three fields as `app/rkhost/src/rupp.rs`, same subtypes:

| | field | value |
| --- | --- | --- |
| TLV1 subtype 1 | `NetStackTokenValue` | base64 in the join script → 16 bytes |
| TLV1 subtype 2 | server token | learned from Reply2 |
| TLV2, handshake | RCC address + `NetStackPort` | |
| TLV2, established | RCC address + `ServerConnections[0].Port` | |

TLV2's port is subtype-dependent; advertising `NetStackPort` after the handshake
black-holes every datagram. Verified with a hand-built `OpenConnectionRequest1`
from the page: Reply1 comes back 28 B, `0x7e`, mtu 1200.

## Networking split

| traffic | path | why |
| --- | --- | --- |
| roblox.com API hosts (`rbx-net.js` list) | frame, `credentials: include` | needs the cookie; Roblox only echoes ACAO for `*.roblox.com` |
| `clientsettingscdn.roblox.com` | direct from the IWA | `access-control-allow-origin: *`, and it is where the transport flag lives — `rbx-net.js` rewrites `FFlagUseRbxTransportClient3` to `"False"` on the way in |
| `*.rbxcdn.com` assets | direct from the IWA | public, CORS-open |

Workers cannot reach the frame, so they reach the page over a
`BroadcastChannel("rbxnet")` instead of borrowing the engine's postMessage
protocol. `rkhost` prepends that prelude to `WebClient.js` in `--iwa` mode.

## CSP, and the two things it forces

The IWA policy is fixed: `script-src 'self' 'wasm-unsafe-eval'`,
`require-trusted-types-for 'script'`, no inline script, no localhost.

* **No inline script.** Loader globals and the ABI live in `.js` files.
* **Trusted Types.** `script.src = ...`, `new Worker(...)` and `importScripts()`
  all need a policy object. `boot.js` installs one (`__tt`) and patches
  `HTMLScriptElement.prototype.src` and `Worker`, so engine code that assigns
  `src` directly still works.

## Running it (dev mode)

```bash
# 1. serve
./app/rkhost/target/debug/rkhost --iwa --root iwa --port 8770 \
  --wasm build/WebClient.patched.wasm --engine-dir /tmp/opencode/rw \
  --cdn-base https://setup.rbxcdn.com/webclient/version-75f1039cb4964863-RobloxWebClient

# 2. install once (flag only works on a fresh browser start)
google-chrome --user-data-dir=~/.weblox-iwa \
  --enable-features=IsolatedWebApps,IsolatedWebAppDevMode \
  --install-isolated-web-app-from-url=http://127.0.0.1:8770/ \
  --no-first-run about:blank

# 3. the origin it assigned
grep -o "isolated-app://[a-z0-9]*" ~/.weblox-iwa/Default/Preferences
# open isolated-app://<id>/?placeId=13569002876
```

Only manifest changes need a reinstall; source changes are live because the
dev-mode proxy forwards to the server.

`--cdn-base` matters: rkhost otherwise derives the CDN path from the
`--engine-dir` directory name, which 403s and leaves the engine on defaults.

## Known rough edges

* **Loading-screen thumbnails are blocked.** `tr.rbxcdn.com` sends no CORP
  header, and a COEP page refuses it:
  `ERR_BLOCKED_BY_RESPONSE.NotSameOriginAfterDefaultedToSameOriginByCoep`.
  Cosmetic; the game renders. Fix is to route thumbnails through the frame or
  to a blob.
* **No packaging yet.** Dev-mode install is per-machine and flag-gated. Signing
  a web bundle is the only path to something installable by someone else.
* **The old path still exists.** `host/`, the rkhost WebSocket bridge and
  `app/src-tauri` are untouched and still work; they are dead weight once the
  IWA is the only target.
